# API 設計核心

本文件定義前後端共用的資料概念、可用操作與行為規則。交付範圍見 [README](../README.md)，實作分工見 [framework.md](framework.md)；具體路徑、HTTP 方法與欄位格式於實作時訂定。

## 資料與關係

| 對象 | 定義 |
|---|---|
| 模型 | 提供模型資訊與可設定的推論參數 |
| 範例 | 系統提供的影像，具有適用模型的關係；前端只選擇範例，不提供上傳 |
| 流程 | 保存選定模型、選定的一張適用範例、推論參數與 random seed 設定；對外最多對應一個 run、一個 analyse |
| 推論（run） | 屬於唯一流程，依該流程設定對同一張影像執行多次完整推論 |
| 分析（analyse） | 屬於唯一流程，使用同一流程已完成 run 的輸出，產生不確定度分析結果 |
| 報表 | 彙整該流程實際執行的設定、模型與範例資訊及推論與分析成果 |

## 可用操作

| 對象 | 操作與主要內容 |
|---|---|
| 模型 | 查詢模型清單、模型資訊與可設定參數 |
| 範例 | 查詢模型適用範例，取得範例資訊與原圖 |
| 流程 | 依初始設定建立流程；查詢、修改、刪除流程 |
| run | 開始或重新執行推論；查詢狀態、進度與結果；修改、取消、刪除 |
| analyse | 開始或重新執行分析；查詢狀態、進度與結果；修改、取消、刪除 |
| 報表 | 請求產生並查看該流程的報表 |

## 共用規則

### 執行與結果

- 建立流程只保存設定；開始推論才建立並執行 run。重複請求不增加第二個對外的 run 或 analyse。
- run 為 `COMPLETED` 才可建立或執行 analyse；同一流程的 run 與 analyse 皆為 `COMPLETED` 才可產生報表。
- 查詢任務可取得狀態、目前階段與進度更新時間；run 另提供已保存的完整推論輸出數量，失敗時提供原因。
- analyse 的結果包含像素涵蓋比例熱圖、輪廓疊圖、CDclust 分群與代表圖及群比例，三者使用同一組目標遮罩。計算與解讀見 [不確定度流程設計](xtool/uncertainty.md)。

### 修改、重新執行與 ID

- 開始推論後仍可修改流程設定，但須捨棄既有 run 與 analyse 的執行內容及成果，並清除依賴它們的報表；後續依新設定重新推論與分析。
- 修改或重新執行 run 時，原推論成果及其下游 analyse、報表一併捨棄。修改或重新執行 analyse 時，捨棄原分析成果與報表，保留已完成的 run。
- 修改或後端執行失敗時，前端用來識別對應物件的 ID 不變；失敗後重新執行也沿用該 ID。後端可依情況修改既有紀錄或刪除重建；使用者主動刪除時才移除對外物件。
- 被捨棄的執行內容及成果不可再作為目前結果；舊工作的後續回報不得覆寫新狀態或恢復舊成果。

### 取消與刪除

- 取消執行中的任務須先進入 `CANCELING`，確認停止後才為 `CANCELED`；尚未派送的任務須先阻止執行。run 失敗或取消後不可執行 analyse；analyse 失敗或取消不改變已完成 run 的狀態。
- 刪除流程時，一併刪除其 run、analyse、報表與成果檔案。刪除 run 時，其 analyse、報表與相關成果一併刪除；刪除 analyse 時，其分析成果與報表一併刪除，保留 run。
- 修改而捨棄舊工作或刪除物件時，須阻止待執行工作，並取消、確認正在執行的工作已停止，再完成相關清除。清除範圍限於該流程或任務所屬資料，系統共用模型與範例不隨之刪除。

### 任務狀態

run 與 analyse 共用以下 `status`。狀態描述執行情形，進度描述目前階段與已完成工作量。

| 狀態 | 意義 |
|---|---|
| `QUEUED` | 任務已建立，等待派送或開始執行 |
| `RUNNING` | 正在執行推論或分析 |
| `COMPLETED` | 工作已完成，所需成果已保存並確認可讀取 |
| `FAILED` | 執行失敗，提供失敗原因 |
| `CANCELING` | 已提出取消要求，等待確認工作停止 |
| `CANCELED` | 已確認工作停止，或已阻止尚未派送的工作 |
